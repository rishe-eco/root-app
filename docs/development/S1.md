## 3 · What the build settled that the plan did not

1. **Money could not wait for J4.** The plan put PD-14's field gating in J4. But S1 hands design and development `contracts.readActive`, so from this stage the fee is one field away from them. S1 therefore gates the three money fields that exist today — `Contract.amount`, the published revision's frozen `amount`, and the draft (now `contracts.author`) — through `mayReadMoney`. **Still open until J4:** the bodies of the *Fees* and *Payment Schedule* articles (J4 adds `Article.sensitive`), and billing reached through other types. The published snapshot's `contentHash` is unaffected — redacting a field of the *view* changes nothing the hash covers.
2. **The builds queue now takes the assignment edge.** The plan's mapping table was silent on `builds.ts`, but it defines `canAuthorBuild`. Leaving the queue open to every developer would let the queue and the demo disagree about whose work a project is, so `phasesForBuilds`, the three project queries, `declareBuild` and `publishBuild` all use `requireBuildAuthorOnProject`. `builds.ts`'s old argument — nothing there returns `Contract!` because a contract carries the fee — still holds, and is now also true of `Contract` itself for a developer.
3. **Projects hold demos; contracts hold assignees.** Until J4 puts a contract on each phase, a developer's claim on a project is "developer of any contract on it" (`canAuthorBuildOnProject`). A project has one contract today, so this is the same answer, written to survive a second.
4. **Authoring guards must not count the customer edge.** `projectVisibleTo` admits a project's own customer (the portal needs that); the authoring guard uses `projectVisibleToStaff`, the staff half alone.
5. **A form needs a list, not just a refusal.** `assignContract`'s write-time checks are only half of an assignment UI: `assignableUsers(job)` returns exactly the accounts it would accept (active, holding the job's capability — ADMIN included, by construction). Answerable only for the two jobs, so it is not a "who holds X" oracle.
6. **Unpublished contracts are visible to staff readers.** `contractVisibleTo` admits a draft to `contracts.readActive` — a designer can be assigned before the customer ever sees the contract, and their first job is often exactly then.
7. **`DONE` is still active** until J11's `deliveredAt` exists: the plan's third clause is absent, not false.

## 5 · Found on review and in the combined run

- **The SDL `Role` enum lacked SALES and DESIGNER** (found by the web lane's e2e): selecting `User.roles` threw for them, `signIn`'s payload included, so neither could sign in. The in-process harness injects the user, so no integration test selected `roles` for those accounts. Fixed, with `roleEnum.test.ts` (the two enums read as text, `changeAction.test.ts`'s trick) and a round-trip in `s1.test.ts`.
- **Half of a contracts-list row was dead for readers** (found by the combined e2e): the status and publish cells stopped the row's click even when they held no control. They now stop it only for authors, and the new specs click the ref cell.
- **`prisma/test-db.ts` retries an unreachable first connection** — the shared Docker Postgres refused connections under load from three lanes at once.
