# T2 — the theme catalogue (the first half of T2 + J8)

**Built:** 2026-09-29 · **Plan:** `root-sot/ecosystem/working/root-studio-journeys-build-plan.md` §5 "T2 + J8" (the catalogue lines only)
**Branch:** `stage-t2-themes` — built by a Sonnet lane (`f5b992f`, `7441084`), reviewed by Opus

A designer keeps the catalogue of pre-made themes — name, vendor, demo URL, preview, RTL support, licence cost, notes — assigns them to template types, and uploads a preview. Nothing on a contract uses them yet: J8 (after J7) proposes rounds of themes to a customer, snapshotting each and copying its preview into a contract-owned design image.

## 1 · What was built

- **Migration `20260929170000_t2_themes`:** `RtlSupport`, `Theme` (with `createdAt` for stable ordering), `TemplateTypeTheme` (composite primary key as the unique pair), `FileClass.THEME_PREVIEW`, `StoredFile.themeId`; **the private-file CHECK widens a second time** (after L7) to admit a theme owner — recorded in the header as an invariant change, proven by direct inserts.
- **`lib/themes.ts`:** `canReadThemes`, `canSeeThemePreview`, `checkDemoUrl` (https only — and **never framed anywhere**: third-party theme demos open in a new tab, per the plan's J8 trap), `parseLicenseCost`.
- **API:** `themes(activeOnly)`, `createTheme`, `updateTheme` (deactivate, never delete — a past round must never lose its theme), `setTemplateTypeThemes` (replace-all under T1's `FOR UPDATE` lock; returns the whole catalogue so the client cache is right on both sides). The preview is uploaded through `/upload` in one step; a replacement deletes the old row and bytes in the same transaction.
- **Web:** Templates → **Themes** («پوسته‌ها» — «قالب» is already "template»), read-only without `templates.types`.

## 2 · Decided

- **`licenseCost` is not behind `money.read`.** It is Root's procurement cost, not a customer's money, and design chooses by it. It stays private because no customer-facing resolver returns a `Theme` — and the schema comment tells J8 to snapshot only name, vendor and demo URL into a round.

## 3 · Found

- **`POST /upload` wrote the `contractId` query parameter onto every file, whatever its class** — a theme preview uploaded with a stray `contractId` would have been readable by that contract's customer, and the CHECK would not have noticed (one owner satisfies it). It now writes only the owner edge the class names. This also means a `contractId` sent with RESEARCH_TEXT or SERVICE_IMPORT is ignored; `files` and `l7` pass.
- `ERR_STREAM_PREMATURE_CLOSE` appears in e2e server logs when a browser closes an image download early (`GET /files/:id`'s `pipeline`). Not changed; not checked whether it predates this stage.
