# J13 — invoices: drafts, numbers, due dates, plan issuing, the invoice view

**Built:** 2026-09-30 · **Plan:** `root-sot/ecosystem/working/root-studio-journeys-build-plan.md` §5 "J13", PD-11, PD-19; journeys Q4, Q11, Q18
**Branch:** `stage-j13-invoices` — built by a Sonnet lane (`465c87f` → `0ae62b2`), reviewed by Opus (`2c4609d`). **Built before J7**, beside J5+J6: signing through the API arrives with J7, so the tests sign by inserting the `Signature` row signing writes.

A billing entry is now an **invoice with a life**: a draft the customer cannot see, then issued — numbered from a sequence, dated, due a number of days later. A contract's payment plan (J4) is issued one row at a time, only once the agreement is signed, the previous row is paid and, for a phase-tied row, the phase's demo is accepted. The customer has **Invoices** («صورت‌حساب‌ها») — a list and a printable single invoice, with no pay button.

## 1 · What was built

- **Migration `20260930130000_j13_invoices`:** `BillingEntry.issuedAt` nullable with no default (null = draft); `invoiceNumber` (unique), `dueAt` (`DATE`, PD-19 — the plan wrote `DateTime`), `paymentTermDays`, `plannedInvoiceId` (unique; FK `Restrict`, so a planned invoice with an invoice cannot be deleted); `CREATE SEQUENCE invoice_number_seq` (PD-11 — a sequence never races; a rollback burns a number, so numbers may skip); backfill numbering existing entries in `issuedAt` order, due the day issued with a term of 0, then `setval`; CHECK **`BillingEntry_issued_is_complete`** (issued ⇒ numbered and dated), proven by direct insert.
- **Libs:** `lib/invoice.ts` — `canIssuePlanned` (`NOT_SIGNED`, `PREVIOUS_UNPAID`, `PHASE_NOT_ACCEPTED`), `plannedInvoiceState`, `isOverdue`, `formatInvoiceNumber` (`INV-000123`, Latin), `takeInvoiceNumber`, `firstInvoicePaidAt`; `lib/steps.ts` `agreementSignedAt` — the one rule for "signed"; `visibility.ts` `invoiceVisibleTo`; `attention.ts` `INVOICE_OVERDUE`; `statusSummary.ts` — *started* and the overdue count; `notify.ts` `INVOICE_ISSUED` (email and SMS, both locales); `env.DEFAULT_PAYMENT_TERM_DAYS` (default 7, a placeholder for the founder; pinned to 7 in the test runners).
- **API:** `createInvoiceDraft` (renames `createBillingEntry`), `updateInvoiceDraft`, `deleteInvoiceDraft`, `issueInvoice`, `issuePlannedInvoice` (under `lockContract` — the lock `setPaymentPlan` takes; the loser of a double press is `ALREADY_ISSUED` and burns no number; the unique `plannedInvoiceId` is the backstop), `markBillingEntryPaid` refuses a draft (`NOT_ISSUED`), `unmarkBillingEntryPaid` refuses once the next planned invoice is issued (`SUCCESSOR_ISSUED`, under the same lock). Customer: `myInvoices` (issued only; replaces `myBillingEntries`), `invoice(id)` (owner, else `NOT_FOUND`), `PlannedInvoice.state / blockedBy / invoice`. The ticket and service-run creators make drafts; the lazy subscription generator issues and numbers each period in its own transaction, sends no notification (a backdated subscription would mail a batch at once), and skips billed periods before taking a number. **J4's owed guard:** `setPaymentPlan` refuses to replace a plan any row of which has been issued (`PLAN_HAS_ISSUED_INVOICES`).
- **Web:** portal `/app/invoices` and `/app/invoices/:id` (printable through `print.css`), `/app/billing` redirects; desk billing — drafts, Issue, a plan card per contract with **Issue next** enabled by the same `canIssuePlanned`; Draft badges on Tickets and Services.

## 2 · Decided

1. **"Signed" is the current contract revision's signature, on both roads** (`agreementSignedAt`). *Review fix:* the lane read the AGREEMENT `StepApproval` as the signature; J7's `approveContract` writes that row **before** the customer signs, so an approved-but-unsigned contract would have issued invoices and counted as started. Tests now sign with a `Signature` and assert an approval alone is `NOT_SIGNED` and not started.
2. **Started:** a contract with no payment plan (every legacy contract) keeps *started = signed*, unchanged; with a plan, signed **and** the first planned invoice paid, `startedAt` the later of the two. Derived, never stored — un-paying un-starts.
3. **Phase-tied invoices** flip on a DEMO `StepApproval` for that `phaseId` — the row J10 will write; tested by inserting it. Until J10 nothing produces it, which is correct (plan trap).
4. Lazy subscription entries: `issuedAt` stays the period start, `dueAt` that day plus the default term.
5. `computeBillingReport` skips drafts, so no report counts one.
6. `INVOICE_OVERDUE`: one line per contract with a count, money-anchored, the customer's move. `INVOICE_DUE` / `INVOICE_ISSUABLE` are declared but not emitted.
7. `resetDatabase` restarts `invoice_number_seq`, so tests can say `INV-000001`.
8. Notification copy uses the formal «شما» (as J4's email does); the web uses «تو».
