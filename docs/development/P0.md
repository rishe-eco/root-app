## 2 · What the build settled that the plan did not know

1. **Production set the cookie name explicitly, twice.** `.env.production.example` and `docker-compose.prod.yml` both said `root_session`, so changing `env.ts`'s default alone — what the plan said — would have changed nothing in production. Found while writing the P0-7 brief; the boot refusal makes an operator's old value fail loudly.
2. **Sign-out would have silently stopped working.** A browser ignores a clearing `Set-Cookie` for a `__Host-` name without `Secure`; `clearSessionCookie` passed `{ path: '/' }` alone. One options source for both now.
3. **The suites had never run on this machine.** npm runs scripts through cmd.exe here; the integration script was a POSIX `VAR=… tsx` prefix; there was no `root_website_test`; `node_modules` lagged the lockfile (`exceljs`); no Chrome (Edge instead); `storage.test.ts` split paths on `/`. The L-stage records' counts were from another machine.
4. **`location = /ask` sends none of the shared security headers** (found by the P0-2 lane). Its responses are SSE/JSON, not documents, so the CSP matters little there — but `nosniff` would. Recorded, not fixed: not D-1's scope. **Owed.**
5. **A worktree's own branch can start stale.** Agent worktrees were created at the commit before the prep merge; two agents noticed and branched from `main` themselves. Every brief since says so explicitly.
